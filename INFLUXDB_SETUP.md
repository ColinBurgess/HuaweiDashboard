# InfluxDB Setup Guide

## Overview

InfluxDB stores time-series telemetry data (inverter readings, statistics, etc.) that enables:
- Historical data analysis
- Statistical trends and anomalies
- Performance metrics across time
- Future advanced analytics and alerting

## Quick Start

### Local Development

1. **Start InfluxDB container:**
   ```bash
   docker compose --profile dev up -d influxdb
   ```

2. **Run the setup script:**
   ```bash
   chmod +x ./backend/scripts/setup-influxdb-v2.sh
   ./backend/scripts/setup-influxdb-v2.sh
   ```

   This script will:
   - Wait for InfluxDB to be ready
   - Check if already configured (idempotent)
   - Create organization (`huawei-dashboard`)
   - Create bucket (`telemetry`)
   - Generate API token
   - Update `.env` with credentials (automatically appended)
   - **IMPORTANT:** The `.env` file is in `.gitignore` and should NEVER be committed

3. **Start application services:**
   ```bash
   docker compose --profile modular up -d
   ```

4. **Verify data is being recorded:**
   - Open http://localhost:8086
   - Login with: `admin` / (password from `.env` INFLUX_PASSWORD)
   - Navigate to Data Explorer
   - Select bucket `telemetry`
   - Look for `telemetry` measurements with fields like `activePower`, `inputPower`, etc.

### Production (Server)

The setup is the same, but you'll run the script on the server before starting docker compose:

```bash
# SSH into server
ssh user@your-server

# Navigate to project
cd /path/to/HuaweiDashboard

# Start just InfluxDB
docker compose --profile modular up -d influxdb

# Run setup script
chmod +x ./backend/scripts/setup-influxdb-v2.sh
./backend/scripts/setup-influxdb-v2.sh

# Start all services
docker compose --profile modular up -d
```

**Important:** The `.env` file generated on the server contains sensitive credentials and must be:
- Kept in `.gitignore` (never committed)
- Protected with appropriate file permissions: `chmod 600 .env`
- Backed up securely if needed
- Treated as a secret file (not shared, not logged)

## What Gets Stored in InfluxDB

The collector service automatically writes:
- `pv1Voltage`, `pv1Current`
- `pv2Voltage`, `pv2Current`
- `activePower`, `inputPower`
- `houseLoad`, `gridPower`
- `batteryPower`, `batterySOC`
- `consumption`, `temperature`

These are stored in the `telemetry` bucket with tags for:
- `model` (inverter model)
- `serial` (inverter serial number)

## Accessing InfluxDB

### Web UI
- URL: http://localhost:8086 (local) or http://your-server:8086 (production)
- Username: `admin`
- Password: Check your `.env` file for `INFLUX_PASSWORD` (generated by setup script)

### Querying with Flux
Example query to get average PV power over the last 24 hours:

```flux
from(bucket: "telemetry")
  |> range(start: -24h)
  |> filter(fn: (r) => r._measurement == "telemetry")
  |> filter(fn: (r) => r._field == "inputPower")
  |> aggregateWindow(every: 1h, fn: mean)
```

## Security & Credentials Management

### ⚠️ IMPORTANT: Never Commit `.env`

The `.env` file is automatically ignored by Git (see `.gitignore`). However, be aware:

1. **`.env` contains secrets:**
   - `INFLUX_TOKEN`: API token for InfluxDB authentication
   - `INFLUX_PASSWORD`: Admin password for InfluxDB
   - `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID`: Sensitive integration credentials

2. **Protection measures:**
   - File is in `.gitignore` - will not be committed
   - Set file permissions to restrict access: `chmod 600 .env`
   - Never share `.env` contents in logs, tickets, or PR descriptions
   - Rotate credentials regularly in production

3. **Server deployment:**
   - Run `setup-influxdb-v2.sh` on the server (not locally) to generate server-specific credentials
   - Store `.env` securely with restricted access
   - Use different credentials for development and production
   - Consider using secrets management (e.g., Docker Secrets, HashiCorp Vault) for production

### Token Rotation

#### Option 1: Non-Destructive Rotation (Preserves Data) ⭐ RECOMMENDED

1. **Generate a new token in InfluxDB:**
   ```bash
   docker exec -it huawei-influxdb influx auth create \
     -o huawei-dashboard \
     -d "HuaweiDashboard API Token (rotated $(date +%Y-%m-%d))"
   ```

2. **Copy the token from output and update `.env`:**
   ```bash
   # Edit .env and replace INFLUX_TOKEN with the new value
   nano .env
   # Then restart services to pick up new token
   docker compose --profile modular restart inverter-collector
   ```

3. **Optionally revoke the old token:**
   ```bash
   # List all tokens
   docker exec -it huawei-influxdb influx auth list -o huawei-dashboard
   
   # Revoke old token (replace TOKEN_ID with the ID from list)
   docker exec -it huawei-influxdb influx auth delete -i TOKEN_ID
   ```

#### Option 2: Complete Reset (Destructive - Loses Data)

Only use if you want to start fresh and lose all historical data:

```bash
# ⚠️  WARNING: This will delete all historical data
rm .env  # or just remove INFLUX_TOKEN line
docker compose down
docker volume rm huaweidashboard_influxdb_data
docker compose --profile dev up -d influxdb
./backend/scripts/setup-influxdb-v2.sh
```

## Troubleshooting

### InfluxDB not responding
```bash
# Check if container is running
docker compose ps influxdb

# View logs
docker compose logs influxdb

# Restart
docker compose restart influxdb
```

### Setup script fails
```bash
# Check InfluxDB health
curl http://localhost:8086/health

# If already setup but you want to reconfigure:
docker compose down
docker volume rm huaweidashboard_influxdb_data
docker compose --profile dev up -d influxdb
./backend/scripts/setup-influxdb.sh
```

### Data not appearing in InfluxDB
1. Verify token in `.env` is correct
2. Check collector service logs: `docker logs huawei-collector-service`
3. Verify InfluxDB connectivity from app: `docker logs huawei-collector-service | grep -i influx`

## Manual Token Generation

If you need to regenerate the API token:

```bash
# Access InfluxDB CLI
docker exec -it huawei-influxdb influx

# Generate new token
influx auth create -o huawei-dashboard -d "HuaweiDashboard API Token"

# Copy the token and update .env
INFLUX_TOKEN=<new-token-here>
```

## Data Retention

Currently configured with unlimited retention (0 seconds = no expiration).

To change retention policy (example: keep 30 days):

```bash
docker exec -it huawei-influxdb influx bucket update \
  --name telemetry \
  --retention 30d
```

## Data Backup & Disaster Recovery

### Automatic Backups

To protect historical data against accidental volume deletion:

```bash
# Create a backup now
./backend/scripts/backup-influxdb.sh

# Backup will be stored in: storage/backups/influxdb/influxdb-backup-TIMESTAMP.tar.gz
```

### Scheduled Daily Backups

Add to your crontab (runs daily at 2 AM):

```bash
crontab -e

# Add this line:
0 2 * * * cd /path/to/HuaweiDashboard && ./backend/scripts/backup-influxdb.sh >> storage/logs/backup.log 2>&1
```

### Backup Features

- ✅ Complete InfluxDB backup (all buckets, tokens, dashboards)
- ✅ Compressed (tar.gz format to save space)
- ✅ Automatic cleanup (keeps last 30 days by default)
- ✅ Timestamped for easy identification
- ✅ Can be transferred to external storage

### Restoring from Backup

If the InfluxDB volume is accidentally deleted:

```bash
# Find the backup file
ls storage/backups/influxdb/

# Restore from backup
./backend/scripts/restore-influxdb.sh storage/backups/influxdb/influxdb-backup-2026-06-17_14-30-45.tar.gz
```

**WARNING:** Restore will delete current InfluxDB data and restore to the backup point in time.

### Production Backup Strategy

For production deployments, consider:

1. **Daily backups:** Use cron to run `backup-influxdb.sh` daily
2. **Off-site backup:** Copy compressed backups to remote storage (S3, cloud provider, etc.)
3. **Monthly archive:** Keep monthly snapshots for long-term retention
4. **Test restore:** Periodically test restore process to ensure backups work

## Future: Regenerating Historical Data

Once InfluxDB is set up and running, historical JSONL files can be regenerated with accurate PV distribution data:

```bash
npm run regenerate:history -- 2026-06-02
```

This requires InfluxDB to have the raw voltage/current data available.
